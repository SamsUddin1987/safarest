ARCHITECTURE RULES
------------------
1. A command-specific implementation belongs in its own file under commands/.
2. Register interactive tools with CAD.registerTool(). Supported handlers include
   onStart, onClick, onPreview, onOption, afterUndo, onEnter and onFinish.
3. Register command names and aliases with CAD.registerCommand().
4. Use CAD.createContext() for controlled access to engine state, entities,
   selection, geometry transforms, history, prompts and tool lifecycle.
5. cad-tools.js is a generic controller. Do not add command-specific algorithms
   or preview implementations there.
6. Load core registry and core engine first, then draw and modify commands,
   followed by interaction, history, command-line, controller, entities,
   keyboard and import modules. Preserve the order in cad_workspace.html.
7. Do not edit staticfiles/js/cad manually. It is generated by collectstatic.

MODIFY COMMAND WORKFLOW
-----------------------
Select target objects before starting MOVE, COPY, ROTATE, SCALE, MIRROR, TRIM
or EXTEND. ERASE can be run with a current selection or followed by selection
and ENTER. See MODIFY_COMMANDS_README.txt for command usage and limitations.

TRIM / EXTEND SCOPE
------------------
TRIM and EXTEND currently work with line/polyline-style BufferGeometry entities.
Unselected linework acts as cutting/boundary geometry. They are not yet full
AutoCAD implementations for arcs, blocks, dimensions, regions or advanced modes.
When a circle or rectangle approximation is trimmed/extended, it becomes a polyline.

VALIDATION
----------
The current MODIFY source files pass Node.js syntax checks and the command/tool
registry registration check. Run the Django application and perform browser-level
interaction tests before deploying to production.

PLINE ESC commits all completed vertices. MOVE displays a translucent cyan moving preview while preserving the original until placement is confirmed.
